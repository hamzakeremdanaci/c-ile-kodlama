01

Kurulum: ilk satırı çalıştır

~5 dakikabaşlangıçterminal

C# için tek ihtiyacımız .NET SDK. Kurduktan sonra dotnet komutu hem proje oluşturur hem derler hem çalıştırır. Konsol uygulaması seçmemizin sebebi basitlik: ekran kartı, pencere, oyun motoru yok. Sadece kod ve mantık.

TERMINALproje oluştur
dotnet --version              # SDK kurulu mu?
dotnet new console -o YilanOyunu
cd YilanOyunu
dotnet run                    # "Hello, World!" yazmalı
DOSYAYilanOyunu/ klasörü
YilanOyunu/
├── YilanOyunu.csproj   ← proje ayarları (hedef .NET sürümü)
├── Program.cs          ← tüm kodumuz buraya
└── bin/  obj/          ← derleme çıktıları (elle dokunma)

Mantığı

  1. Proje = bir klasör + bir .csproj dosyası. dotnet new console ikisini de hazırlar, sıfırdan dosya yazmana gerek yok.
  2. Program.cs içindeki Main metodu giriş noktasıdır. Program çalışınca ilk orası çalışır; oyunumuzun tamamı bu dosyada olacak.
  3. Derleme ayrı, çalıştırma ayrı. dotnet build hataları gösterir, dotnet run gerekirse derleyip çalıştırır.
⚠

Sık yapılan hata: 'dotnet' is not recognized hatası alıyorsan SDK ya kurulu değildir ya da terminal, kurulum sonrası açılmamıştır. Terminali kapatıp yeniden aç.

02

Oyun alanını ve koordinatları kur

~10 dakikaveri yapısıstruct

Oyundaki her şey bir hücrede durur: yılanın kafası, gövdesi, yem, duvarlar. Bir hücreyi tarif etmek için iki sayı yeter: sütun (X) ve satır (Y). Bu ikisini her yerde ayrı ayrı taşımak yerine tek bir Konum tipinde topluyoruz. Aşağıdaki satırların hepsi class Program içine yazılır.

C#Program.cs — ayarlar
using System;
using System.Collections.Generic;
using System.Diagnostics;
using System.Text;
using System.Threading;

const int Genislik = 30;   // kaç sütun
const int Yukseklik = 20;  // kaç satır

// Ekranda kullanacağımız semboller
const char Bos = ' ';
const char Duvar = '#';
const char Kafa = '@';
const char Govde = 'o';
const char YemKarakter = '*';

struct Konum
{
    public int X;
    public int Y;

    public Konum(int x, int y)
    {
        X = x;
        Y = y;
    }
}

Mantığı

  1. const = değişmeyecek değer. Alan boyutu oyun sırasında değişmediği için derleyiciye "bu sabit" diyoruz; kodun her yerinde aynı sayıyı tekrar yazmıyoruz.
  2. struct = küçük veri demeti. Sadece iki sayı tuttuğu için sınıf (class) yerine struct kullanıyoruz: bellekte daha hafif, kopyalanması ucuz.
  3. X sağa, Y aşağı artar. Bu bir ekran koordinatıdır. Matematikte Y yukarı gider; burada tam tersi. Yılanı "yukarı" göndermek için Y'yi azaltacağız.
  4. Duvarlar kenarda. 0 ve son indeks duvarlara ayrıldığı için oynanabilir alan 1..Genislik-2 aralığıdır.
  5. Semboller de sabit. Ekranda göreceğin #, @, o, * karakterleri tek yerde tanımlı; görüntüyü değiştirmek istediğinde tek satırı düzeltmen yeter.
◆

İpucu: Koordinatları ekranda gördüğün gibi düşün: sol üst köşe (0, 0), sağa gidince X büyür, aşağı inince Y büyür. Kalan her şey bu iki kuraldan çıkar.

03

Oyunun durumunu tanımla

~10 dakikastateliste

Ekranda gördüğün yılan aslında bir liste. Listenin 0. elemanı kafa, son elemanı kuyruk. Yılan her adımda "kafaya yeni bir hücre ekle, kuyruktan bir hücre sil" mantığıyla ilerler — tıpkı bir tren gibi.

C#Program.cs — durum değişkenleri
static readonly Random rastgele = new Random();

// Yılan: 0. eleman kafa, son eleman kuyruk.
static readonly List<Konum> yilan = new List<Konum>();
static Konum yem;
static Konum yon = new Konum(1, 0);          // şu anki yön (sağ)
static Konum bekleyenYon = new Konum(1, 0);  // tuştan gelen, sıradaki adımda uygulanacak

static int skor;
static int enYuksekSkor;
static int hiz = 8;        // saniyede kaç adım
static bool oyunBitti;

Mantığı

  1. Liste sırası anlam taşır. Kafa her zaman yilan[0]. Yön ve çarpışma hesaplarında hep bu elemandan başlıyoruz.
  2. Yön bir vektördür. (1, 0) sağ, (-1, 0) sol, (0, -1) yukarı, (0, 1) aşağı. Yeni konum = eski konum + yön.
  3. static kullanıyoruz. Tek bir oyun olduğu için bu değişkenlerin sınıfın kendisine ait olması yeterli; nesne oluşturma derdinden kurtuluyoruz. Oyunu büyütürsen bunları bir Oyun sınıfının alanlarına taşımak doğru adım olur.
  4. bekleyenYon neden ayrı? Tuş her basıldığında yönü anında değiştirseydik, iki adım arasında basılan tuşlar yılanı kendi üstüne kıvırabilirdi. Tuşu biriktirip adım anında uyguluyoruz.
⚠

Sık yapılan hata: Yılanı Konum[] dizisiyle tutup sabit boyut varsaymak. Yılan büyüdüğü için boyutu değişen bir yapı gerekir — bu yüzden List<Konum>.

04

Oyun döngüsü: kalp atışı

~12 dakikagame loopStopwatch

Oyunun kalbi tek bir döngüdür: girdiyi oku → kuralları uygula → ekranı çiz. Bu üç işi saniyede hiz kadar tekrarlıyoruz. Yılanın "kayarak" değil de adım adım ilerlemesinin sebebi bu: her turda tam bir hücre hareket var.

C#Program.cs — OyunDongusu()
var saat = Stopwatch.StartNew();
double sonAdim = 0;

while (!oyunBitti)
{
    double simdi = saat.Elapsed.TotalSeconds;

    // Adım zamanı geldiyse oyunu güncelle.
    if (simdi - sonAdim >= 1.0 / hiz)
    {
        sonAdim = simdi;
        YonOku();   // 1) girdi
        Adim();     // 2) kural
        Ciz();      // 3) ekran
    }

    // Kısa bekleme: işlemciyi yormadan döngüyü canlı tut.
    Thread.Sleep(5);
}

Mantığı

  1. 1.0 / hiz = iki adım arası süre. hiz = 8 ise her adım arası 0,125 saniye. Hız artarsa bu süre kısalır, oyun hızlanır.
  2. Neden Thread.Sleep(125) değil? Uyursak tuşları da kaçırırız: 125 ms boyunca basılan ok tuşu işlenmez. Kısa kısa (5 ms) uyuyup her turda saati kontrol etmek, hem işlemciyi yormaz hem girdiyi kaçırmaz.
  3. Neden Stopwatch? Gerçek zamanı ölçer; kare atlamalarını (bilgisayar yavaşlarsa) tolere eder. Sabit sayıda uykuyla değil, gerçekten geçen süreyle karar veriyoruz.
  4. Sıra önemli: önce oku, sonra güncelle, en son çiz. Ters sırada çizersen ekranda hep bir adım geriden gelen bir yılan görürsün.
◆

İpucu: "Hız" hissi sadece bu döngüden gelir. Aynı kurallarla hiz = 3 yavaş ve düşündürücü, hiz = 20 ise refleks oyunu olur.

05

Girdi: tuşları beklemeden okumak

~12 dakikainputvektör

Konsolda Console.ReadKey() çağırırsan program tuş gelene kadar durur. Oyun saniyede 8 kez akmak zorunda olduğu için önce "bekleyen tuş var mı?" diye sorup sadece varsa okuyoruz. Buna engellemeyen (non-blocking) girdi denir.

C#Program.cs — YonOku()
while (Console.KeyAvailable)
{
    ConsoleKeyInfo tus = Console.ReadKey(true);  // true: tuşu ekrana basma
    Konum istenen = yon;

    switch (tus.Key)
    {
        case ConsoleKey.UpArrow:
        case ConsoleKey.W:
            istenen = new Konum(0, -1);
            break;
        case ConsoleKey.DownArrow:
        case ConsoleKey.S:
            istenen = new Konum(0, 1);
            break;
        case ConsoleKey.LeftArrow:
        case ConsoleKey.A:
            istenen = new Konum(-1, 0);
            break;
        case ConsoleKey.RightArrow:
        case ConsoleKey.D:
            istenen = new Konum(1, 0);
            break;
    }

    // 180 derece dönüşü engelle: zıt yönlerin toplamı (0, 0) eder.
    if (istenen.X + yon.X != 0 || istenen.Y + yon.Y != 0)
    {
        bekleyenYon = istenen;
    }
}

Mantığı

  1. KeyAvailable "şu an okunmayı bekleyen tuş var mı?" sorusudur. while ile tüm bekleyen tuşları tüketiyoruz; aksi hâlde tuş kuyruğu birikir.
  2. ReadKey(true) tuşu alır ama ekrana yazmaz. false versen her tuşta ekranda çöp karakterler belirir.
  3. Yön = birim vektör. Sadece yönü değiştiriyoruz, hızı değil. (0, -1) yukarı demek çünkü ekranda Y aşağı artıyor.
  4. Neden anında yon değil de bekleyenYon? İki adım arasında iki tuşa basarsan (örneğin sağ→yukarı→sol), anında uygulama yılanı kendi üstüne sokar. Biriktirip adımda uygulamak bu kazayı engeller.
  5. 180° kuralı: zıt yönlerin toplamı (0,0) eder. Sağa giderken sol reddedilir; aşağı/yukarı ise kabul edilir.
⚠

Sık yapılan hata: Console.KeyAvailable yerine Console.ReadKey() kullanmak. Oyun, tuşa basana kadar donar; yılan durur ama döngü de durduğu için hız ayarı hiç çalışmaz.

06

Bir adım: hareket ve çarpışma

~18 dakikaoyunun kalbiçarpışma

İşte oyunun tamamı burada. Bu fonksiyon çağrıldığında yılan tam bir hücre ilerler ve tüm kurallar sırayla uygulanır. Dikkat et: sıra, kuralların kendisi kadar önemli.

C#Program.cs — Adim()
static void Adim()
{
    yon = bekleyenYon;

    Konum kafa = yilan[0];
    Konum yeniKafa = new Konum(kafa.X + yon.X, kafa.Y + yon.Y);

    // 1) Duvara çarptı mı?
    if (yeniKafa.X <= 0 || yeniKafa.X >= Genislik - 1 ||
        yeniKafa.Y <= 0 || yeniKafa.Y >= Yukseklik - 1)
    {
        oyunBitti = true;
        return;
    }

    // 2) Kendine çarptı mı? Son parçayı saymıyoruz:
    //    yem yemediysek o parça bu adımda kaybolacak.
    for (int i = 0; i < yilan.Count - 1; i++)
    {
        if (yilan[i].X == yeniKafa.X && yilan[i].Y == yeniKafa.Y)
        {
            oyunBitti = true;
            return;
        }
    }

    // 3) Yeni kafayı başa ekle.
    yilan.Insert(0, yeniKafa);

    // 4) Yem yendi mi?
    if (yeniKafa.X == yem.X && yeniKafa.Y == yem.Y)
    {
        skor += 10;
        if (skor > enYuksekSkor)
        {
            enYuksekSkor = skor;
        }

        if (skor % 50 == 0 && hiz < 20)
        {
            hiz++;
        }

        YemUret();
        // Kuyruğu silmiyoruz: yılan bir kare uzar.
    }
    else
    {
        // Yem yoksa kuyruğu sil: boy aynı kalır, yılan kayar.
        yilan.RemoveAt(yilan.Count - 1);
    }
}

Mantığı

  1. Önce hayali kafayı hesapla. Yılanı henüz değiştirmeden "bir sonraki hücre neresi?" sorusunu yanıtlıyoruz: kafa + yön.
  2. Duvar = oyun sonu. Oynanabilir alan 1 ile Genislik-2 arası. Dışına çıkan kafa duvara çarpmış demektir; return ile fonksiyondan çıkıp hiçbir şeyi değiştirmiyoruz.
  3. Kendine çarpma için son parça hariç. Yem yemediysen kuyruk bu adımda silinecek; dolayısıyla kuyruğun eski yerine girmek serbesttir. Kuyruğu da sayarsan oyun haksız yere biter.
  4. Hareket = başa ekle + sondan sil. Bu iki işlem birlikte yılanı kaydırır. Yem yenmediyse son eleman silinir, uzunluk sabit kalır.
  5. Büyüme = kuyruğu silmemek. Yem yendiğinde sadece yilan.Add yapmıyoruz; kuyruğu silmiyoruz. Böylece yılan bir hücre uzar ve yeni kafa yemin olduğu yerde kalır.
⚠

Sık yapılan hata: Yeni kafayı listeye ekledikten sonra kendine çarpma kontrolü yapmak. O anda yeni kafa zaten listede olduğu için yılan her adımda kendine çarpmış gibi görünür. Kontrol, ekleme yapılmadan önce olmalı.

07

Yem, skor ve hızlanma

~12 dakikarastgelelikskor

Yem, oyunun tek rastgele öğesi. Ama "rastgele" demek "kuralsız" değil: yem yılanın üstüne doğmamalı, duvarın içinde kalmamalı ve oyun sırasında yer değiştirmemeli.

C#Program.cs — YemUret()
static void YemUret()
{
    do
    {
        yem = new Konum(rastgele.Next(1, Genislik - 1),
                        rastgele.Next(1, Yukseklik - 1));
    }
    while (yilan.Exists(parca => parca.X == yem.X && parca.Y == yem.Y));
}

Mantığı

  1. Next(1, Genislik - 1) üst sınırı hariç tutar. Yani 1 ile 28 arasında üretir; duvarlar (0 ve 29) hiç seçilmez.
  2. do / while = "geçerli olana kadar dene". Önce rastgele bir yer seçiyoruz, yılanın üstündeyse baştan seçiyoruz. Bu yüzden şartı do'nun sonunda kontrol ediyoruz.
  3. Exists + lambda listedeki her parçayı tek tek gezer. parca => ... şeklindeki kısa fonksiyonlara lambda denir; "şu şartı sağlayan eleman var mı?" demenin kısa yolu.
  4. Skor ve hız: her yem 10 puan. Her 50 puanda hiz bir artar ama 20'de durur — yoksa oyun bir süre sonra oynanamaz hâle gelir.
⚠

Sık yapılan hata: new Random()'ı döngünün veya fonksiyonun içinde oluşturmak. Aynı milisaniyede kurulan Random'lar aynı tohumu kullanır ve hep aynı sayıyı üretir; yem hep aynı yere düşer. Bir kez oluştur, her yerde aynı nesneyi kullan.

08

Çizim: titremeyen ekran

~15 dakikarenderStringBuilder

İlk denemelerde herkes Console.Clear() çağırıp yeniden çizer. Sonuç: göz yoran bir titreme. Çözüm basit — ekranı temizlemek yerine tek seferde yeni kareyi yazmak.

C#Program.cs — Ciz()
static void Ciz()
{
    var ekran = new StringBuilder();

    ekran.Append("  Skor: ").Append(skor)
         .Append("    En iyi: ").Append(enYuksekSkor)
         .Append("    Hız: ").Append(hiz)
         .Append(Environment.NewLine);

    for (int y = 0; y < Yukseklik; y++)
    {
        for (int x = 0; x < Genislik; x++)
        {
            char karakter = Bos;

            if (x == 0 || x == Genislik - 1 || y == 0 || y == Yukseklik - 1)
            {
                karakter = Duvar;
            }
            else if (x == yem.X && y == yem.Y)
            {
                karakter = YemKarakter;
            }
            else
            {
                for (int i = 0; i < yilan.Count; i++)
                {
                    if (yilan[i].X == x && yilan[i].Y == y)
                    {
                        karakter = (i == 0) ? Kafa : Govde;
                        break;
                    }
                }
            }

            ekran.Append(karakter);
        }

        ekran.Append(Environment.NewLine);
    }

    // Tek bir Write ile yazınca ekran titremez.
    Console.SetCursorPosition(0, 0);
    Console.Write(ekran.ToString());
}

Mantığı

  1. Önce bellekte kur, sonra bas. Her hücre için ayrı Console.Write yapmak yerine tüm kareyi StringBuilder'da biriktiriyoruz. Tek yazma işlemi = tek yenileme = titremesiz görüntü.
  2. İmleci başa al. SetCursorPosition(0, 0) yeni kareyi eskisinin üzerine yazar; ekranı silmeye gerek kalmaz.
  3. Karakter önceliği: duvar → yem → yılan. Sırayı değiştirirsen yem duvarın altında kalır ya da yılan yemi örter.
  4. (i == 0) ? Kafa : Govde üçlü operatör: kafa için farklı, gövde için farklı karakter. Görsel ayrım tamamen buradan geliyor.
◆

İpucu: Console.CursorVisible = false; satırı imleci saklar. Yarım kalan bir kare bile görünmez olur; oyun anında daha profesyonel durur.

09

Oyun sonu ve yeniden başlatma

~12 dakikastate machinetemiz çıkış

Oyun bitince programın kapanması kötü bir deneyim. Bir dış döngüyle "oyna → bitir → yeniden başlat" akışını kuruyoruz. Durumu sıfırlayan tek bir fonksiyon olduğu için yeniden başlatmak sadece onu çağırmak demek.

C#Program.cs — Main()
static void Main()
{
    Console.OutputEncoding = Encoding.UTF8;
    Console.CursorVisible = false;
    Console.Title = "Yılan Oyunu - C#";

    // Ctrl+C ile çıkıldığında imleci geri getir.
    Console.CancelKeyPress += (gonderen, olay) =>
    {
        Console.CursorVisible = true;
        Console.ResetColor();
    };

    while (true)
    {
        OyunuBaslat();     // durumu sıfırla
        OyunDongusu();     // oyunBitti olana kadar oyna
        OyunBittiEkrani(); // skoru göster, tuş bekle
    }
}
C#Program.cs — OyunuBaslat()
static void OyunuBaslat()
{
    Console.Clear();
    yilan.Clear();

    int ortaX = Genislik / 2;
    int ortaY = Yukseklik / 2;

    // Kafa listenin 0. elemanı. 3 parçalı başlıyoruz.
    yilan.Add(new Konum(ortaX, ortaY));
    yilan.Add(new Konum(ortaX - 1, ortaY));
    yilan.Add(new Konum(ortaX - 2, ortaY));

    yon = new Konum(1, 0);
    bekleyenYon = yon;
    skor = 0;
    hiz = 8;
    oyunBitti = false;

    YemUret();
    Ciz();
}

Mantığı

  1. Dış while (true) = oyun oturumu. İçerideki döngü oyunBitti olunca biter; dış döngü hemen yeni bir oyun kurar. Bu yapıya durum makinesi (state machine) denir: oyna / bitir / bekle.
  2. Yeniden başlatma = durumu sıfırlama. Tüm değişkenler tek bir fonksiyonda başlangıç değerine dönüyor. "Yeni oyun"u başka yerde tekrar yazarsan bir gün bir değişkeni sıfırlamayı unutursun.
  3. Yılan 3 parça doğar. Kafa ortada, gövde sola doğru; yönü sağ olduğu için kendi üstüne doğmaz.
  4. Temiz çıkış. Ctrl+C programı öldürür ama imleci saklı bırakır. CancelKeyPress olayına bağlanarak çıkmadan önce imleci geri açıyoruz.

Sözlük

Kafa karıştıran 12 terim

Bu kelimeleri bilirsen geri kalan her şey daha anlaşılır olur.

state (durum)
Oyunun "şu anki hâli": yılanın parçaları, yönü, skoru. Ekranda gördüğün her şey bu veriden üretilir.
game loop
Saniyede defalarca tekrarlanan döngü. Girdi → güncelleme → çizim sırasıyla çalışır.
grid (ızgara)
Oyun alanını oluşturan satır ve sütunlar. Her hücrenin bir X ve Y koordinatı vardır.
vektör
Yönü iki sayıyla anlatan çift: sağ (1,0), yukarı (0,-1).
çarpışma
İki nesnenin aynı hücreye denk gelmesi. Kontrol her zaman hareketi uygulamadan önce yapılır.
frame (kare)
Ekranın bir kez çizilmiş hâli. 8 adım/saniye = saniyede 8 kare.
tick
Döngünün bir turu. Yılan her tick'te tam bir hücre hareket eder.
buffer
Ekrana basmadan önce kareyi biriktirdiğin geçici alan. Titremeyi önler.
lambda
x => x > 5 gibi kısa, isimsiz fonksiyon. Exists gibi metotlara şart vermek için kullanılır.
struct
Birkaç küçük değeri bir arada tutan hafif veri tipi. Koordinat için ideal.
refactor
Davranışı değiştirmeden kodu düzenlemek. Tekrar eden parçaları fonksiyona taşımak gibi.
delta time
İki güncelleme arasında geçen süre. Hız hesabını bu süreye göre yapınca oyun her bilgisayarda aynı hissi verir.

Bu oyunu nereye taşıyabilirsin?

Aynı mantık, daha büyük araçlar. Yılan bittiğinde sırada bunlar var.

Cila kolay

Renkler, ses efektleri (Console.Beep), duraklatma tuşu, zorluk seçimi, en yüksek skoru dosyaya kaydetme.

Kod kalitesi orta

Her şeyi tek dosyadan çıkar: Oyun, Yilan, Tahta sınıfları. Test edilebilir, büyüyebilir bir yapı.

Grafik orta

MonoGame veya SDL2 ile aynı oyunu piksellerle çiz. Mantık birebir aynı kalır, sadece Ciz() değişir.

Oyun motoru ileri

Unity: C# bilgin burada aynen geçerli. Update() döngüsü, GameObject ve collider kavramları tanıdık gelecek.

Web'e taşı ileri

Aynı kuralları tarayıcıda JavaScript/Canvas ile yaz. Bu sayfadaki laboratuvar tam olarak bunun küçük bir örneği.
